# Documents and file storage

Module `core.documents` (in `ENABLED_MODULES=default`). It's usable once storage is configured. Code: `apps/api/src/core/storage/`, `modules/documents/`. Tests: `test/documents.test.ts`.

## Storage (deployment-level, one per installation)

| | Docker Compose | AWS (Terraform) |
|---|---|---|
| Driver | `STORAGE_DRIVER=local`, `STORAGE_PATH=/app/storage` on the `app-storage` volume | `STORAGE_DRIVER=s3` with the installation's private documents bucket (KMS, versioned, TLS-only) |
| Backup | `bin/backup` writes the DB dump **and** `…documents.tar.gz` (both checksummed). `bin/restore` restores both | AWS Backup (daily, bucket + RDS) and bucket versioning |
| Limit | `STORAGE_MAX_FILE_MB` (default 10, max 50) | same |

Object keys are generated by the application only: `<org>/employees/<employee>/<uuid>` or `<org>/company/<uuid>`. User file names never become paths. The local driver writes atomically, with files mode 600 in folders mode 700.

## Categories (HR-configured)

Code and name; scope `employee` or `company`; visible to the employee (own documents, or all employees for company documents); employee may upload their own; **restricted** (medical, identity: needs `documents.restricted`); expiry date required.

## Who sees what

| Who | Sees |
|---|---|
| `documents.read` (HR Admin, HR Executive, Payroll, Auditor) | All documents except restricted categories |
| `documents.restricted` (HR Admin) | Restricted categories too |
| Every employee | Their own documents in employee-visible categories, and company documents in employee-visible categories |
| Managers | No implicit access to their team's documents |

Uploads need `documents.manage`, or the employee's own record in a category that allows employee upload. Archiving needs `documents.manage` (never deleted; files are retained).

## Safety

- File type is detected **from content**: PDF, PNG, JPEG, WebP, DOCX, XLSX. The client's file name and content type are ignored. PDFs with JavaScript, launch actions, embedded files or rich media are rejected.
- Downloads are `Content-Disposition: attachment`, `nosniff`, `no-store`, and the API's `default-src 'none'` CSP.
- SHA-256 is stored at upload and verified on every download (tampering returns `integrity_failed`).
- Every upload, download and archive is in the audit log; downloads of restricted documents are flagged.
- **Not yet:** antivirus/malware scanning (planned hook: ClamAV sidecar for Compose, GuardDuty Malware Protection for S3). Until then only the formats above are accepted, and active PDF content is refused.

## Expiry reminders

The `documents.expiry` job (daily 08:00) notifies the employee and all `documents.manage` holders 30 days and 7 days before expiry, and on the expiry date, once each.
